# Aon 웹사이트

Node.js 내장 SQLite를 사용하는 Aon 소개 사이트입니다. 공개 페이지에는 Aon 소개와 업로드 이미지가 표시되고, `/admin.html`에서 편집 키로 로그인하면 이미지 업로드 및 사이트 CSS 편집이 가능합니다. 임의의 서버 파일이나 프로그램 코드는 편집할 수 없습니다.

## 실행 (Windows)

`run.bat`을 더블클릭하면 아래 작업을 자동으로 수행합니다.

- Node.js 22.13 이상이 없으면 `winget`으로 Node.js LTS 설치를 시도합니다. SQLite는 Node.js 내장 기능을 사용해 Visual Studio C++ 도구 설치가 필요 없습니다. 설치 완료 후 이 창에서 Node를 찾을 수 없다는 메시지가 나오면 창을 닫고 `run.bat`을 한 번 더 클릭하세요.
- `.env`가 아직 없으면 편집 키와 세션 비밀값을 자동 생성합니다. 이때 표시되는 편집 키를 저장해 두세요.
- 필요한 npm 패키지를 설치하고 서버를 시작한 뒤 브라우저에서 사이트를 엽니다. 기존 설치가 실패했더라도 다시 클릭하면 패키지 설치를 재시도합니다. 서버 로그가 표시되는 `Aon server` 창은 사이트를 사용하는 동안 열어 두세요.

직접 설정하고 실행하려면 Node.js 22.13 이상을 설치하고, 프로젝트 폴더에서 `npm install` 후 `npm start`를 실행하면 됩니다. `.env.example`을 복사해 `.env`를 만들고 비밀값을 설정할 수도 있습니다.

`.env`에서:
   - `SITE_EDIT_KEY`: 관리자용 편집 키. `.env`에만 저장하며 공개하지 마세요.
   - `SESSION_SECRET`: 32자 이상의 무작위 문자열. 예: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`
   - 사용자가 지정한 `akdhs323=gayok?` 키를 쓰려면 `SITE_EDIT_KEY` 값으로 설정합니다. 공개 사이트에서는 추측하기 쉬운 키 대신 더 긴 비밀 키를 권장합니다.

사이트는 `http://localhost:3000`, 편집 화면은 `http://localhost:3000/admin.html`입니다. 편집 키는 편집 화면에서 입력합니다.

## GitHub Pages 배포

`main` 브랜치의 `public/` 파일 변경은 GitHub Actions가 GitHub Pages에 자동 배포합니다. 도메인 `aon69446.p-e.kr`은 저장소의 `CNAME` 파일에 설정되어 있습니다. DNS의 A 레코드는 GitHub Pages IPv4 주소로 지정되어 있어야 합니다.

GitHub Pages는 정적 호스팅이므로 공개 Aon 문서는 표시되지만, Node.js 서버와 SQLite가 필요한 CSS 저장, 로그인, 이미지 업로드 API는 Pages에서 실행되지 않습니다. 이 기능은 `run.bat`으로 실행하는 별도 Node.js 서버에서만 작동합니다. Pages의 편집 링크는 정적 호스팅의 이 제한과 문서 소스 수정 경로를 안내합니다.

SQLite 데이터베이스는 `data/aon.sqlite`에 생성되고 이미지 파일은 `public/uploads/`에 저장됩니다. 두 위치를 정기적으로 백업하세요.

## 외부 공개 및 유동 IP

Deco 포트포워딩은 이미 다음과 같이 설정되어 있습니다.

- 서비스 종류: `HTTP` (서비스 이름은 표시용)
- 내부 IP: `192.168.68.54`
- 프로토콜: `TCP`
- 내부 포트: `3000`
- 외부 포트: `3000`

앱 서버도 `0.0.0.0:3000`에서 실행하므로 이 설정에 맞습니다. `run.bat`으로 서버를 켠 뒤 외부 방문자는 **`http://aon69446.p-e.kr:3000`** 으로 접속하면 됩니다. 포트가 `3000`이므로 주소 뒤에 `:3000`을 붙여야 합니다. 이 구성에서는 Caddy, 80/443 포트 설정이 필요하지 않습니다.

현재 연결은 **상위 공유기 → Deco → 서버 PC** 구조라고 확인했습니다. 이중 공유기 환경에서는 Deco의 포트포워딩 한 번만으로 외부 접속이 되지 않을 수 있습니다. 포트가 두 공유기를 통과하도록 다음 두 규칙이 필요합니다.

1. Deco 앱에서 서버 PC `192.168.68.54`로 TCP `3000`을 전달합니다. 이 규칙은 이미 설정되어 있습니다.
2. 상위 공유기 설정에서 외부 TCP `3000`을 **상위 공유기가 Deco에 할당한 WAN 주소**로 전달합니다. 해당 주소와 포트를 Deco 규칙이 다시 PC `192.168.68.54:3000`으로 전달합니다. 상위 공유기에서 Deco의 WAN 주소를 DHCP 예약해 두면 주소가 바뀌는 것을 막을 수 있습니다.
3. 상위 공유기의 인터넷/WAN IPv4가 실제 공인 IP `115.138.61.26`인지 확인합니다. 상위 공유기의 WAN도 사설 주소이거나 `100.64.0.0`~`100.127.255.255` 범위라면 통신사 쪽 추가 NAT일 수 있으므로, 통신사에 공인 IPv4 할당을 문의하거나 상위 공유기에서 브리지 모드를 설정해야 합니다.

사용자가 알려준 `192.168.68.1`은 **장치 정보 화면에 나온 주소**이므로, Deco의 인터넷/WAN IP라고 확인된 값이 아닙니다. 포워딩 대상에 임의로 입력하지 마세요. Deco 앱의 인터넷 연결 상태에서 Deco WAN IP를 별도로 확인하고, 상위 공유기의 장치 목록에서 같은 주소로 Deco가 연결돼 있는지도 확인하세요.

`내도메인.한국`의 도메인 설정 화면에서 DNS의 A, AAAA, CNAME, TXT 레코드를 편집할 수 있습니다. 현재 루트 도메인(`aon69446.p-e.kr`)은 A 레코드에 공인 IP를 넣어 사용하고 있습니다. 화면의 이름 입력칸을 비워 두면 기본 도메인 자체에, 이름을 입력하면 해당 하위 도메인에 레코드가 적용됩니다(예: `www`).

DNS 레코드 변경은 도메인이 가리키는 주소를 바꾸는 기능이고, 공유기의 포트포워딩을 대신하지는 않습니다. 상위 공유기에서 포트 전달을 할 수 없고 브리지 모드/DMZ도 사용할 수 없다면, 기존 주소에 직접 접속시키는 방식은 동작하지 않습니다. 대안으로 터널을 쓰려면 터널 제공자가 사용자 도메인을 지원하고 안내된 DNS 레코드(예: `www`의 CNAME)를 발급해야 합니다. CNAME은 보통 기존 A 레코드와 같은 이름에 함께 설정할 수 없으므로, `aon69446.p-e.kr`의 현재 A 레코드를 보존한 채 별도 이름(예: `www.aon69446.p-e.kr`)으로 연결하는 방식이 적절할 수 있습니다. 루트 도메인을 터널로 연결할 수 있는지는 서비스가 루트 도메인 또는 ALIAS/ANAME 방식을 지원하는지 확인해야 합니다. 터널 서비스의 실제 대상 주소를 받기 전에는 현재 A 레코드를 수정하지 마세요.

처음 외부 접속을 시험할 때는 집 Wi-Fi가 아니라 휴대전화의 Wi-Fi를 끄고 모바일 데이터로 접속하세요. 같은 집 네트워크에서 공인 주소로 시험하면 Deco의 NAT loopback 지원 여부에 따라 실패할 수 있습니다. `run.bat` 실행 때 Windows 방화벽 안내가 나오면 Node.js의 개인 네트워크 접속을 허용하세요. 방화벽이 차단 중이면 관리자 PowerShell에서 다음 규칙을 추가할 수 있습니다: `New-NetFirewallRule -DisplayName "Aon HTTP 3000" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow`

현재 DNS 조회에서 `aon69446.p-e.kr`은 `115.138.61.26`을 가리켰습니다. 유동 IP가 바뀌면 `내도메인.한국`의 `A` 레코드도 새 IP로 갱신해야 합니다. 계정 전용 DDNS 갱신 방식은 공개 페이지에서 확인할 수 없어 자동 갱신은 설정하지 않았습니다.

주의: 현재 Deco 설정은 암호화되지 않는 HTTP입니다. 공개 페이지와 이미지 열람은 가능하지만, 이 주소로 편집 키를 입력하면 네트워크에서 보호되지 않을 수 있습니다. 편집 키는 신뢰할 수 있는 네트워크에서만 입력하세요. HTTPS를 사용하려면 별도로 80/443 포트와 HTTPS 프록시 설정이 필요합니다.

편집 화면에서 업로드한 이미지는 앱의 공개 `/uploads/` 경로에서 제공되므로 방문자에게도 보입니다. 현재 업로드는 이미지 형식만 지원하고 파일당 최대 8MB입니다.
